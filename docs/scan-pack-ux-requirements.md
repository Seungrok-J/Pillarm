# 스캔 결과 — 포(Pack) 만들기 UI/UX 요구사항

> 약봉투 스캔 인식 결과 확인 화면(`ScanResultScreen.tsx`)의 "포 만들기" 기능에 대해
> 그동안 사용자가 요청/확인한 UI·UX 요구사항을 모아둔 문서. 관련 코드를 다시 만지기 전에 읽을 것.

## 배경 — 포(Pack)란

약국에서 실제로 포장하듯, **같은 시간에 함께 먹는 여러 약을 하나의 포로 묶어서** 홈 화면에서 한 번의 탭으로 전부 복용 체크할 수 있게 하는 기능. 같은 약이 시간대가 다른 여러 포에 걸쳐 속할 수 있다.

예시 (2026-08-25 세션에서 사용자가 제시한 실제 케이스):
> 약1, 3, 5 → "아침·저녁 포" / 약1, 5 → "점심 포"(약3은 졸림 성분 때문에 점심 제외) / 나머지는 개별 등록

## 데이터 모델

```ts
interface Pack {
  id: string;
  name: string;
  times: string[];       // 이 포가 적용되는 복용 시간(들)
  memberIdxs: number[];  // 이 포에 속한 약들의 인덱스
}
```

- 최초 화면 진입 시, **완전히 동일한 시간 조합**을 가진 약이 2개 이상이면 자동으로 기본 포를 생성한다.
- 이후 사용자가 시간·멤버를 자유롭게 편집하거나 "+ 새 포 만들기"로 포를 추가할 수 있다.
- 저장 시(`handleCreate`), 약 1개가 여러 포에 속하면 포별로 별도의 Schedule row를 생성한다(같은 medicationId, 다른 packetId). 포에 속하지 않은 나머지 시간은 개별 Schedule로 별도 생성한다.
- **같은 약이 같은 시간에 두 포에 동시에 속할 수는 없다** — 그러면 같은 시각에 알림이 중복 발생한다. 시간이 겹치는 두 포가 동시에 같은 약을 점유하는 건 항상 막아야 한다.

## 요구사항 1 — 포 만들기 흐름이 직관적이어야 한다 (2026-08-25)

**문제**: "시간 칩을 먼저 선택 → 그 시간을 만족하는 약이 후보로 나타남 → 체크"라는 2단계 흐름이 사용자에게 바로 와닿지 않았다. 특히 어떤 약이 왜 후보 목록에 안 보이는지(이미 다른 포에 속해 있어서 숨겨짐)가 설명되지 않아 "포 만들기가 막혔다"고 오해하게 됨.

**요구사항**:
- 각 포 카드에서 어떤 약이 왜 선택 가능/불가능한지 화면에서 바로 보여야 한다. 조건에 안 맞아 후보에서 사라지는 것과, 다른 포에 이미 속해서 후보에서 사라지는 것을 구분해서 사용자가 이해할 수 있어야 한다.

## 요구사항 2 — 모든 약이 이미 한 포에 들어가 있어도 새 포를 또 만들 수 있어야 한다 (2026-08-25)

**문제 상황**: 이미 만들어둔 포가 특정 시간대의 약을 전부 점유하고 있을 때, "+ 새 포 만들기"로 같은 시간대를 다시 골라도 후보 약이 하나도 안 뜨고 "선택한 시간을 모두 가진 약이 없어요"라는, 실제 원인(이미 다른 포에서 다 가져감)과 무관해 보이는 메시지만 나와 포 만들기가 막힌 것처럼 보였다.

**요구사항**: 포 만들기는 절대 막다른 길이 되면 안 된다. 이미 다른 포에 속한 약이라도, 사용자가 원하면 그 약을 새 포로 옮길 수 있어야 한다(기존 포에서 자동으로 빠지고 새 포에 들어감).

**적용한 수정** (`ScanResultScreen.tsx`, 2026-08-25):
- `candidateIdxsFor`: 다른 포에 이미 속한 약도 후보 목록에 포함시키도록 변경(이전엔 필터링되어 아예 안 보였음).
- `claimedByOtherPack`: 특정 약이 시간이 겹치는 다른 포에 이미 속해 있는지 확인하는 헬퍼 추가.
- 후보 목록 렌더링: 다른 포에 속한 약은 체크박스 옆에 "◯◯포에 있음 · 탭해서 옮기기" 태그를 표시.
- `togglePackMember`: 다른 포에 속한 약을 체크하면, 그 다른 포에서는 자동으로 제거하고 이 포로 옮긴다(같은 시간에 중복 등록되는 걸 방지하면서도 항상 재배치가 가능하게 함).
- 포 섹션 안내 문구에 "다른 포에 있는 약도 탭하면 이 포로 옮겨져요" 추가.

## 요구사항 3 — 일정관리 화면의 드래그앤드랍 병합 (2026-08-25, 참고용)

포 만들기와 별개로, 이미 등록된 일정끼리 합치는 `ScheduleManageScreen.tsx`에는 길게 눌러 드래그해서 포로 합치는 기능이 있다(`react-native-draggable-flatlist` 기반). 복용 시간과 기간(시작일·종료일)이 완전히 같을 때만 병합 허용, 다르면 Alert로 거부. 드래그 중 카드 확대 애니메이션 + 햅틱 피드백(시작: Medium, 성공: Success, 거부: Warning).

스캔 결과 화면의 포 만들기는 아직 체크박스 방식이라 이 드래그앤드랍만큼 직관적이지 않을 수 있다 — 추후 스캔 결과 화면에도 비슷한 드래그 기반 인터랙션을 도입하는 걸 고려해볼 것.

## 요구사항 4 — 인식 정확도를 높여서 자동 포 생성이 더 잘 되게 (2026-08-25)

**요청**: 약봉투/처방전 이미지의 "투약량·횟수·일수" 표와 "①아침 ②점심 ③저녁 ④취침전" 체크박스, "식후30분/식전30분" 체크박스를 AI가 더 명시적으로 읽어서 정확한 복용 시간을 계산하면, 그 결과 같은 시간을 갖게 된 약들이 자동으로 한 포로 묶이는 기존 로직이 더 잘 작동하게 된다.

- **일일 복용 횟수 계산**: `timesPerDay = 표의 "횟수" ÷ "일수"` (예: 횟수 6, 일수 3 → 1일 2회). `durationDays`는 "일수" 값을 그대로 사용.
- **복용 시점(아침/점심/저녁/취침전) 인식**: 이미지에 "①아침 ②점심 ③저녁 ④취침전" 체크박스가 있고 체크(☑)돼 있으면 그 항목만 사용. 체크를 못 읽으면 timesPerDay 기반 추론(`inferMealSlots`)으로 폴백.
  - 아침/점심/저녁 = 사용자가 앱 설정에 저장한 식사 시간.
  - 취침전 = 고정 시간이 없으므로, 화면에서 사용자가 체크하면 시간 피커가 떠서 직접 지정.
- **식후/식전 30분 인식 + 수동 적용**: 이미지의 "식후30분/식전30분/공복/식후즉시/식사직전" 체크박스를 인식해 `withFoodMinutes`로 반영. 화면에서도 "식전 30분/식후 30분/무관" 버튼을 누르면 실제로 체크된 시점들의 시간이 ±30분 이동하도록(기존엔 라벨만 바뀌고 시간에 반영 안 되던 버그성 동작이었음).

**적용한 수정**:
- 서버 `server/src/routes/aiScan.ts`의 Claude Vision 프롬프트에 위 3가지 규칙 추가 (표 기반 횟수 계산, 체크박스 기반 mealSlots, 체크박스 기반 withFoodMinutes). **주의: 이 변경은 Railway에 재배포해야 실제 스캔에 반영된다 — 아직 배포 전.**
- 클라이언트 `scanUtils.ts`: `MedicationScanResult`에 `mealSlots`/`manualTimes`/`bedtimeTime` 필드 추가. `suggestTimesFromMeals`에 `bedtimeOverride`/`noFallback` 옵션 추가.
- `ScanResultScreen.tsx`: 기존 "아침/점심/저녁" 3개 단축 버튼을 "아침/점심/저녁/취침전" 4개 체크 방식으로 교체(취침전은 탭하면 시간 피커). "식전/식후" 세그먼트 버튼이 실제로 시간을 ±30분 재계산하도록 연결. "+ 시간 추가"로 넣은 수동 시간과 시점 기반 시간을 구분해서 합치도록 재구성.

## 요구사항 5 — 취침전 시간 재설정, 전체 선택, 포 이름 자동 채우기 (2026-08-25)

- **취침전 재설정**: 취침전을 한 번 선택한 뒤에도 버튼을 다시 탭하면(해제가 아니라) 시간 피커가 다시 떠서 재설정할 수 있어야 함. 완전히 해제하려면 별도의 작은 ✕로 구분.
  - 적용: `toggleMealSlot`이 `bedtime`일 때 항상 피커를 열도록 변경(기존엔 이미 선택된 상태면 그냥 해제됐음), 버튼 우상단에 작은 ✕(`onRemoveMealSlot`)를 추가해 명시적 해제와 재설정을 구분.
- **포 만들기 전체 선택 유지**: 후보로 뜬 약 전체를 한 번에 담는 기능이 있어야 함(다른 포에 있던 약은 자동으로 이 포로 옮겨짐). "전체 해제"도 함께 제공.
  - 적용: `selectAllCandidates`/`deselectAllMembers` 추가, 후보 목록 위에 "전체 선택 · 전체 해제" 텍스트 버튼 표시.
- **포 이름 자동 채우기**: 인식 결과(시간·식전후)를 분석해서 포 이름을 예시처럼 자동으로 채워줌 — 예: 아침 시간 하나면 "아침약", 식후로 통일돼 있으면 "아침약(식후)". 사용자가 이미 이름을 직접 입력했으면 자동으로 덮어쓰지 않음.
  - 적용: `suggestPackName(times, memberIdxs, items, mealSettings)` 추가 — 설정된 아침/점심/저녁 시간과 ±35분 이내로 가까우면 그 시점 라벨을 사용, 멤버들의 식전/식후가 전부 같으면 접미사로 붙임. 최초 자동 그룹핑 시점과, 사용자가 포의 시간·멤버를 바꿀 때(이름이 비어있을 때만) 둘 다 적용.

## 미해결 / 추가로 살펴볼 만한 것

- 포 시간 칩(`allTimes`)에 식사시간 프리셋(예: "아침 09:00")과 AI가 인식한 개별 시간(예: "09:30")이 비슷하지만 별개의 칩으로 같이 나열되어 다소 헷갈릴 수 있음 — 병합하거나 시각적으로 구분할지 검토.
- 체크박스 방식 대신 드래그앤드랍으로 포를 만드는 인터랙션(요구사항 3 참고) 도입 여부.
