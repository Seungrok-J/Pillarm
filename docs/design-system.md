# 필람(Pillarm) 디자인 시스템

> 현재 코드베이스(각 화면의 `StyleSheet`, `src/utils/themeManager.ts`)에서 실제로 쓰이고 있는 값을 기준으로 정리한 문서.
> 새 화면·컴포넌트를 만들 때 이 문서의 값을 우선 재사용하고, 새 값이 필요하면 이 문서도 같이 업데이트할 것.

## 1. 컬러

### 1.1 테마 토큰 (`src/utils/themeManager.ts`)

앱은 포인트로 구매하는 "테마샵" 기능이 있어 컬러가 완전 하드코딩이 아니라 토큰화되어 있다. 기본값은 다음과 같고, 대부분의 화면은 아직 `primary`를 `#3b82f6`로 하드코딩해서 쓰고 있다(테마 적용이 전면 반영된 상태는 아님).

| 토큰 | 기본(default) | 설명 |
|---|---|---|
| `primary` | `#3b82f6` | 버튼, 배지, 강조 텍스트, FAB |
| `primaryLight` | `#eff6ff` | 강조색의 연한 배경(뱃지·선택 상태 배경) |
| `background` | `#f9fafb` | 화면 배경(SafeAreaView) |
| `surface` | `#ffffff` | 카드·입력창 배경 |
| `text` | `#111827` | 본문 진한 텍스트 |
| `textSecondary` | `#6b7280` | 보조 텍스트 |

구매 가능한 다른 테마(민트 `#10b981`, 코랄 `#f43f5e`, 라벤더 `#8b5cf6`, 선셋 `#f97316`)도 같은 구조(`primary`/`primaryLight`/`background`/`surface`/`text`/`textSecondary`)로 정의돼 있다 — 새 컴포넌트를 만들 때 `primary`를 하드코딩하지 말고 이 구조를 참고하면 테마 전환 대응이 쉬워진다.

## 2. 타이포그래피

폰트는 시스템 기본 폰트 사용(별도 커스텀 폰트 없음). `App.tsx`에서 `allowFontScaling = false`를 전역 적용하고 있어(단, PRD 접근성 원칙과 상충 소지 있음 — 아래 5번 참고), 폰트 크기 자체를 accessibility 기준(16sp 이상)에 맞춰 잡는 게 특히 중요하다.

| 용도 | 크기 | 굵기 |
|---|---|---|
| 화면 큰 제목 | 22–24px | 800(extrabold) |
| 섹션/카드 제목 | 16–20px | 700(bold) |
| 본문 | 14–16px | 400–600 |
| 보조 설명 | 12–13px | 400–600 |
| 캡션/힌트 | 11px | 400–600 |
| 버튼 텍스트 | 14–16px | 600–700 |

## 3. 간격·모양

| 요소 | 값 |
|---|---|
| 카드 radius | 14–16px |
| 버튼 radius | 10–12px |
| 칩/필(pill) radius | 20px (완전 둥근 형태) |
| 모달/바텀시트 radius | 16–24px (위쪽 모서리만 둥글게 하는 경우 많음) |
| 카드 내부 padding | 16px |
| 화면 좌우 padding | 20px |
| 요소 간 gap | 8px(촘촘) / 12–14px(일반) |
| 카드 그림자 | `shadowOpacity: 0.05`, `shadowRadius: 6`, `elevation: 1` (은은하게) |
| 모달/오버레이 그림자 | `shadowOpacity: 0.15–0.2`, `shadowRadius: 12–20`, `elevation: 8–10` (뚜렷하게) |

## 4. 컴포넌트 패턴

- **카드**: 흰 배경 + radius 14–16 + 은은한 그림자. 포(packet)로 묶인 카드는 `#e0eaff` 톤의 보더로 구분(`borderWidth: 1.5`).
- **세그먼트 버튼**(식전/식후/무관 등): 나란히 배치, 선택 시 `primary` 배경 + 흰 텍스트, 미선택 시 연한 보더 + 회색 텍스트.
- **칩(chip)**: 완전 둥근 radius 20, 선택 시 `primaryLight` 배경 + `primary` 텍스트/보더.
- **체크박스형 항목**: 22×22 둥근 사각형(radius 6), 선택 시 `primary` 배경 + 흰 체크마크.
- **시간 선택(`TimeWheelSheet`)**: 시간을 고르는 UI 는 앱 전체에서 이 컴포넌트 하나만 쓴다. 오전/오후 · 시 · 분 드럼롤 바텀시트이고, 분은 5분 단위다. 일정의 복용 시간 목록(`TimePickerList`)과 설정의 단일 시간 항목이 공유한다. 시트 안의 "직접 입력" 필드는 보조 수단이라 휠 아래에 작게 둔다. **새로 시간 입력 UI 를 만들지 말 것** — 2026-09-04 이전까지 설정 화면만 `HH:mm` 텍스트 입력을 쓰고 있었고, 고령 사용자에게 부담이라 이 컴포넌트로 통일했다. 값 표시는 `formatTimeKo()` 로 "오후 11:00" 형태를 쓴다(24시간제보다 읽기 쉽다).
- **커스텀 확인창(`AlertModal`, 2026-08-26 추가·같은 날 아이콘 뱃지로 개편)**: 시스템 `Alert.alert` 대신 사용. 중앙 정렬 카드(radius 28) + 원형 아이콘 뱃지(72px, 연한 톤 배경 + Ionicons 아이콘 — 이모지 아님) + 제목 + 설명 + 버튼(기본은 `tone` 색상 배경, 취소는 연회색, destructive는 연빨강 배경+빨강 텍스트). `tone`(`primary`/`success`/`danger`/`warning`)이 아이콘 뱃지 색과 기본 버튼 색을 함께 결정 — 앱 전체에서 쓰는 시맨틱 컬러(1.2절)와 동일한 값. `src/components/AlertModal.tsx`. "로그인이 필요합니다" 류의 프롬프트를 포함해 여러 화면(MainTabNavigator, ScanScreen, ScheduleFormScreen, SettingsScreen 등)에 적용돼 있음 — 새 확인창을 만들 때 이모지 대신 이 컴포넌트 + Ionicons 아이콘 이름을 쓸 것.
- **포(packet)는 하나의 단위로 다룬다(2026-08-26)**: DB상으로는 여전히 약마다 별도 Schedule row(같은 packetId로 묶임)지만, UI에서는 포를 일반 일정처럼 "수정"/"삭제" 두 버튼만 있는 카드로 보여준다. 카드에는 약 종류 목록을 노출하지 않고 일반 일정 카드와 동일하게 시간·기간만 보여준다(2026-08-26). "수정"은 `PacketEditScreen`(`src/app/schedule/PacketEditScreen.tsx`)으로 이동해 포 이름·시간·기간을 한 번에(모든 멤버에 동기화) 바꾸고, 멤버 약을 추가("+ 이 포에 약 추가" → `ScheduleNew`에 `presetPacket` 프리셋 전달, 시간·기간 고정)/제거("빼기" → 포에서 분리해 개별 일정으로 전환, 멤버가 1개 이하로 줄면 포 자동 해제)할 수 있다. 새로 포 관련 화면을 만들 때 이 패턴(포 = 한 화면에서 다루는 단위)을 따를 것.
- **포 만들기는 드래그가 아니라 선택 방식(2026-08-26)**: `ScheduleManageScreen`에 있던 "일정을 길게 눌러 다른 일정 위로 끌면 포로 합칠 수 있다"는 드래그 병합 기능(및 `MergeAnimation` 컴포넌트, `react-native-draggable-flatlist`)은 제거됐다 — 포는 스캔 결과 화면(`ScanResultScreen`)에서만 만들 수 있다. 사용자가 추후 "여러 일정을 선택해서 포로 묶는" 형태를 원한다고 밝혔으니, 관리 화면에 포 생성 기능을 다시 넣게 되면 드래그가 아니라 체크박스 선택 방식으로 만들 것.

## 5. 접근성 (CLAUDE.md 핵심 원칙과 연결)

- 글씨 크기 최소 16sp, 터치 영역 최소 44×44pt — 2026-08-26에 스캔 화면 "전체 선택/전체 해제" 버튼이 이 기준 미달이라 지적받아 44pt 이상으로 수정한 사례 있음(`docs/scan-pack-ux-requirements.md` 참고). 새 터치 요소를 만들 때 처음부터 이 기준으로 만들 것.
- `App.tsx`가 전역으로 `allowFontScaling = false`를 강제하고 있음 — OS 글씨 크기 설정을 무시한다는 뜻이다. 레이아웃 보호를 위한 의도적 선택이고, **그 대체 수단으로 앱이 자체 글씨 크기 배율을 제공한다**(2026-09-03 완성).

### 글씨 크기 배율 (앱 자체)

- 설정 → **화면 → 글씨 크기**에서 `보통(1.0)` / `크게(1.15)` / `아주 크게(1.3)` 세 단계. 값은 `user_settings.font_scale`에 저장된다.
- 적용은 **`src/components/AppText.tsx`의 `AppText`·`AppTextInput` 래퍼가 전담**한다. 화면마다 fontSize를 곱하지 않는다.
- **새 화면을 만들 때 `react-native`의 `Text`/`TextInput`을 직접 import 하지 말 것.** 대신:
  ```tsx
  import { AppText as Text, AppTextInput as TextInput } from '../../components/AppText';
  ```
  이렇게 alias로 가져오면 JSX는 그대로 쓰면서 배율이 자동 적용된다. 앱 전체가 이 방식으로 통일돼 있다.
- 래퍼는 `fontSize`와 함께 **`lineHeight`도 같은 비율로 키운다** — fontSize만 키우면 줄이 겹쳐 오히려 읽기 어려워진다.
- **고정 폭(width) 컨테이너 안에 텍스트를 넣을 때 주의.** 배율이 커지면 글자가 잘린다. 실제로 `DoseCard` 왼쪽 시간 컬럼이 `width: 46` 고정이라 배율 1.0에서도 "09:00"이 "09:…"로 잘리고 있었다(2026-09-03 수정). 자세한 규칙은 아래 [좁은 화면·큰 배율 대응](#좁은-화면큰-배율-대응-2026-09-10) 참고.

### 좁은 화면·큰 배율 대응 (2026-09-10)

폴더폰(갤럭시 폴더2 급, 480×800 hdpi = **320dp**)에 글씨 크기 '아주 크게'를 걸면
레이아웃이 읽을 수 없는 수준으로 깨지는 문제가 다수 발견돼 정리했다. 원인은 하나다 —
**`AppText`는 글자만 키우고, 그것을 담는 컨테이너의 고정 `width`·`numberOfLines`·
"한 줄에 N개" 배치는 그대로**다.

#### 기준 기기

**320dp × 533dp**(폴더폰 + '아주 크게')를 하한으로 잡는다. 화면 좌우 padding 20을
빼면 실제로 쓸 수 있는 폭은 **280dp** 뿐이다. 새 화면을 만들면 이 조건에서 한 번
확인할 것 — 안드로이드 스튜디오에 `Folder_Phone_480x800` AVD가 있다.

#### 판정 훅 두 개

증상은 같아도 원인이 둘이라 화면마다 조건을 흩뿌리면 서로 어긋난다. 판정은 이 둘만 쓴다.

| 훅 | 조건 | 언제 쓰나 |
|---|---|---|
| `useCompactLayout()` (`src/utils/compactLayout.ts`) | `fontScale > 1 \|\| width < 360` | 보통 배율의 폴더폰에서도 깨지는 것 |
| `useLargeFont()` (`src/utils/fontScale.ts`) | `fontScale > 1` | 보통 배율이면 320dp에서도 멀쩡한 것 |

둘을 구분하는 게 중요하다. 전부 `useCompactLayout()`으로 묶었더니 보통 배율에서 3열이
멀쩡히 들어가던 통계 지표 타일까지 2+1로 접혀서 오히려 나빠졌다. **"보통 배율 320dp에서
이미 깨지는가?"를 먼저 확인하고 훅을 고를 것.**

#### 규칙

1. **텍스트를 담는 컨테이너에 고정 `width`를 쓰지 않는다.** 꼭 필요하면 폭도 배율을
   따라가게 한다 — `scaledFont(BASE_WIDTH, fontScale)`. 기준값은 상수로 빼서 스타일과
   계산이 같은 값을 보게 한다(`DoseCard`의 `LEFT_TIME_WIDTH`, `HistoryScreen`의
   `TIME_COL_WIDTH` 참고). 아이콘 칸이라면 `width` 대신 `minWidth`로 충분한 경우가 많다.
2. **가로 배치는 좁은 화면·큰 배율을 전제로 설계한다.** 한 줄에 3개 이상을 나란히 두려면
   좁을 때 어떻게 풀지를 같이 정해야 한다. 실제로 쓴 방법은 셋이다.
   - **세로로 쌓기** — 설정의 글씨 크기 세그먼트, 스캔 수정 폼의 식전/식후/무관,
     일정 추가의 시작일/종료일
   - **`flexWrap`으로 접기** — 통계 지표 타일(3 → 2+1), 스캔 수정 폼의 복용 시점(4 → 2×2),
     색상 팔레트(6 → 5+1)
   - **남는 폭을 나눠 갖기** — 그룹 참여 코드 입력칸 6개(`flex: 1` + `maxWidth`)
3. **고정 크기 × N이 280dp를 넘는지 계산해 볼 것.** 배율과 무관하게 넘치는 경우가 실제로
   있었다. 색상 팔레트는 `6 × 44 + 5 × 10 = 314dp`라 마지막 색이 화면 밖으로 밀려
   **보통 배율에서도 아예 고를 수 없었다.** 이건 배율 문제가 아니라 산수 문제다.
4. **자르기(`numberOfLines={1}`)는 마지막 수단.** 자르면 정보가 사라진다. 스캔 결과의
   복용 시간이 `09:30 · 17:...`로 잘려 두 번째 시간과 하루 횟수가 통째로 사라진 적이 있다.
   좁을 때 두 줄을 허용하는 쪽이 대개 낫다(`numberOfLines={compact ? 2 : 1}`).
   같은 카드 안의 형제 행들이 어떻게 하고 있는지부터 볼 것.
5. **세로도 유한하다.** 533dp에서 상단 고정 영역이 커지면 정작 목록이 안 보인다. 홈의
   "다음 복용 예정" 배너가 4줄로 늘어 화면 절반을 먹었고, 기록 화면의 월간 달력은 6줄을
   고정으로 차지해 복용 목록에 100px도 남지 않았다. 화면 상단에 고정으로 놓는 요소는
   **줄 수 상한을 정하고**, 큰 것은 접을 수단을 준다(기록 화면의 주간 스트립 ↔ 월간 펼치기).
6. **떠 있는 요소가 액션 버튼을 가리지 않게.** 홈의 FAB이 복용 카드의 완료 버튼과 겹쳐
   "탭 1회 복용 완료"가 막혔다. 리스트 영역이 짧을수록 겹칠 확률이 올라간다 — 좁을 때는
   리스트 끝의 전체 폭 버튼으로 내렸다.
7. **`AlertModal` 버튼은 알아서 쌓인다.** 큰 배율이면서 네 글자 이상인 라벨이 있으면
   세로로 전환된다(`계속 등록` 같은 라벨이 쪼개지던 문제). 확인창을 새로 만들 때 따로
   신경 쓸 필요는 없지만, 라벨은 짧게 쓰는 편이 여전히 낫다.

## 6. 아이콘 — 아직 통일 안 됨 (진행 중, 2026-08-26)

- **문제**: 이모지(💊 📅 ⏰ 🍽️ 🎉 등)와 `@expo/vector-icons`(Ionicons, 예: `logo-apple`/`logo-google`/`chatbubble`/`pencil`/`close-circle`)가 화면마다 섞여서 쓰이고 있고, 앱 아이콘(`assets/icon.png`, 그라디언트+글로시 알약+종+플러스뱃지)·알림 아이콘(`assets/notification-icon.png`, 플랫 흰색 실루엣)·스플래시 아이콘이 서로 다른 스타일로 각자 만들어진 상태.
- **작업 예정**: 사용자가 브랜드 마크(알약/종 모티프) 방향을 직접 정한 뒤, 앱 아이콘 · 스플래시 · 알림 아이콘 · 로그인 화면 로고(현재 💊 이모지) 등 브랜드 마크가 쓰이는 자리를 전부 같은 마크로 통일할 예정. 후보 스타일 6종(심플 알약 / 알약+종 / 배지형 / 아웃라인 / 알약+플러스뱃지 / 투톤 알약)을 샘플 이미지로 전달했고, 사용자가 나중에 최종 방향을 정해서 알려주기로 함 — **이 결정이 오기 전까지 아이콘/스플래시 관련 파일을 임의로 바꾸지 말 것.**
- 기능적 UI 이모지(📅 ⏰ 🍽️ 등 화면 곳곳의 보조 아이콘)까지 전부 커스텀 아이콘으로 바꾸는 건 논의된 적 없음 — 브랜드 마크(알약·종 모티프)만 통일 대상.

## 7. "AI 슬롭" 방지 원칙 (2026-08-26, [taste-skill](https://github.com/leonxlnx/taste-skill) 중 RN에 적용 가능한 것만 발췌)

taste-skill은 웹(Tailwind/React) 전용 스킬이라 그대로 설치하진 않았고, 앱에도 통하는 원칙만 뽑아왔다. 새 화면을 만들거나 리뷰할 때 체크리스트로 참고할 것.

**레이아웃**
- box-in-box-in-box 중첩 금지 — 카드 안에 카드 안에 카드 넣지 말고, 컨테이너 수를 줄이고 위계를 직접적으로 표현할 것.
- 여백이 숨쉬게 — 화면 블록 사이 간격을 넉넉히, 내부 padding은 깔끔하게. 빽빽하고 산만한 레이아웃 금지.
- 화면마다 미묘하게 다르게 — 상단 구성, 이미지/텍스트 비율, 밀도, CTA 위치를 화면마다 조금씩 바꾸되 제품 전체의 톤은 일관되게. 모든 화면이 똑같은 템플릿처럼 찍혀나오면 안 됨.
- 첫 화면(진입 화면)은 포커스 하나만 — 첫 진입 화면에 통계·칩·태그·약한 CTA를 잔뜩 욱여넣지 말 것.
- "항상 단순하게"가 아니라 "항상 깔끔하게" — 정보가 많아도 읽기 쉽고 정돈돼 있으면 됨. 밋밋한 템플릿보다 의도가 담긴 레이아웃이 낫다.

**타이포그래피**
- 글씨가 작게 느껴지면 디자인이 안 끝난 것 — 본문/제목/버튼이 조금이라도 작아 보이면 내용을 줄이더라도 글씨는 줄이지 말 것 (CLAUDE.md 16sp 최소 원칙과 같은 결).
- 제목/본문/라벨의 굵기·크기 위계를 뚜렷하게 — 전부 같은 굵기로 두지 말 것.

**모션 (react-native-reanimated)**
- `transform`(scale/translate)과 `opacity`만 애니메이션할 것 — 레이아웃에 영향 주는 속성(width/height/margin 등)을 애니메이션하면 성능이 떨어짐.
- 애니메이션을 넣기 전에 "이게 뭘 전달하는가?"를 먼저 물을 것 — 위계, 상태 변화, 피드백 전달이 아니라 "그냥 있으면 있어 보여서"는 넣지 않는다.
- **미해결**: 기기 접근성 설정의 모션 축소(reduce motion)를 지금 앱이 존중하지 않음 — RN에서는 `AccessibilityInfo.isReduceMotionEnabled()` / `prefersReducedMotion` 훅으로 체크해서 향후 연출성 애니메이션을 넣을 때 고려할 것.

**아이콘·비주얼**
- 아이콘 팩에서 대충 고른 듯한 기본 아이콘 대신, 일관된 선/면 로직을 가진 아이콘 세트를 쓸 것 — [섹션 6](#6-아이콘--아직-통일-안-됨-진행-중-2026-08-26)의 아이콘 통일 작업과 같은 문제의식.
- 화면마다 새 화면을 만들 때 팔레트 로직·타이포 분위기·간격 체계·모서리 radius 로직·아이콘 스타일·내비게이션 모델·버튼 스타일을 이 문서(디자인 시스템 문서) 기준으로 고정해서 제품 정체성이 흔들리지 않게 할 것 — 이 문서를 유지하는 이유 자체가 이 원칙임.
- 이유 없는 반복 요소 금지 — 근거 없는 통계 카드 반복, 텅 빈 큰 카드, 필 배지·작은 라벨 남발 금지. 요소 하나하나가 제품 로직을 담당해야 함.

**색상**
- 화면당 강조색은 하나, 한번 정하면 그 화면 전체에서 일관되게 — 지금 앱의 테마 토큰 구조(1.1)와 이미 같은 방향.

**미해결 — 다크모드**: 현재 `app.json`이 `userInterfaceStyle: "light"`로 라이트 모드만 지원. taste-skill은 "두 모드를 처음부터 같이 설계하라"고 권장하지만, 지금 앱은 다크모드 지원 계획이 없음 — 나중에 필요해지면 이 문서의 컬러 토큰(1절)에 다크 변형을 추가하는 식으로 확장할 것.
